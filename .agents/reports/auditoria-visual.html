Design System — Bistro POS

Todo lo visual que existe hoy en la app, renderizado para que lo veas tal cual: colores, fuentes, sombras, radios y las inconsistencias que arrastra el proyecto.

▸Resumen ejecutivo

Bistro POS usa React 19 + TypeScript + Vite 6, con Tailwind CSS cargado por CDN y la configuración de tema escrita inline dentro de index.html (no hay tailwind.config.js ni archivo central de tokens). Existe una base de tema decente (paleta ámbar "Warm Bistro", tipografía, sombras card), pero está poco adoptada: la mayoría de pantallas escribe colores, radios y sombras directamente a mano, creando mucha deuda visual.

En una frase: hay el esqueleto de un sistema de diseño, pero casi nadie lo usa. Los valores se repiten a mano por todo el código, generando decenas de variantes casi iguales.

6Movimiento

~25 animaciones activas, repartidas entre la config inline, index.css y CSS-in-JS. El easing estándar de facto es cubic-bezier(0.16, 1, 0.3, 1).

Loaders presentes
ScreenLoader
skeleton shimmer
prefers-reduced-motion: NO existe. Con ~25 animaciones activas, no respetar la preferencia de reducir movimiento es un fallo de accesibilidad para usuarios con sensibilidad al movimiento.
Animaciones duplicadas: slideInRight y slideInUpSubtle están definidas dos veces (config inline + index.css) con duraciones/valores distintos (0.25s vs 0.4s; 15px vs 10px).

  4. Tono tipográfico: la app usa pesos muy altos (bold/black por doquier). ¿Mantenemos el look "fuerte" o lo suavizamos a semibold?
